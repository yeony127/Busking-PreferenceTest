# 최애 버스킹 취향 테스트

2026 김포 버스킹 페스티벌 부대 체험 프로그램 — 12문항 취향 테스트 웹앱입니다.
순수 HTML/CSS/JS 한 파일로만 되어 있어서 별도 빌드 과정 없이 바로 배포할 수 있어요.

## 파일 구성

- `index.html` — 웹앱 전체
- `manifest.json` — 태블릿 홈 화면에 추가했을 때 "앱처럼"(주소창 없이) 실행되게 하는 설정 파일
- `sw.js` — 서비스 워커. 앱처럼 설치되게 해주고, 와이파이 없이도 동작하도록 필요한 파일을 태블릿에 저장해둡니다.
- `icons/` — 홈 화면 아이콘 이미지 (192px, 512px, 애플용, 파비콘)
- `fonts/` — 오프라인 작동을 위해 내장한 폰트 파일 (Jua, Noto Sans KR — 이 앱에 쓰인 글자만 담아 용량을 줄였습니다)
- 반드시 **폴더 구조를 그대로 유지**한 채 올려야 합니다(`icons`, `fonts` 폴더가 `index.html`과 같은 위치에 있어야 함).

## GitHub 업로드 방법

1. [github.com/new](https://github.com/new) 에서 새 저장소(Repository)를 만듭니다. (Public/Private 상관없음)
2. 저장소 페이지에서 **Add file → Upload files** 클릭
3. 이 폴더 안의 `index.html`, `manifest.json`, `sw.js`, `README.md`, `icons` 폴더, `fonts` 폴더를 통째로 끌어다 놓습니다. (GitHub 웹 업로드는 폴더째로 끌어다 놓으면 하위 폴더 구조가 그대로 유지됩니다)
4. **Commit changes** 클릭

이미 저장소를 만들어 두셨다면, 같은 화면(Add file → Upload files)에서 `sw.js`와 `fonts` 폴더(그리고 아직 없다면 `manifest.json`, `icons` 폴더)를 추가로 올리고, 기존 `index.html`은 이번에 보내드린 새 버전으로 덮어쓰면(같은 파일명으로 업로드하면 자동으로 덮어쓰기 여부를 물어봅니다) 됩니다.

## Vercel 배포 방법

1. [vercel.com](https://vercel.com) 에 GitHub 계정으로 로그인
2. **Add New → Project** 클릭
3. 방금 만든 GitHub 저장소를 선택 (Import)
4. Framework Preset은 **Other**(정적 사이트)로 두고, 빌드 설정은 건드릴 필요 없이 그대로 **Deploy** 클릭
5. 몇 초 후 `https://프로젝트명.vercel.app` 주소로 바로 접속 가능합니다.

## 와이파이 없이(오프라인) 구동하기

이 앱은 폰트까지 전부 자체 파일로 내장하고(`fonts/` 폴더), 서비스 워커(`sw.js`)가 첫 방문 시 필요한 파일을 태블릿에 저장해두기 때문에 **그 이후에는 와이파이/데이터 연결이 완전히 끊겨도 정상 작동**합니다. 문항 진행, 점수 계산, 결과 화면, 타임테이블, QR코드 생성까지 전부 태블릿 안에서 처리돼요. (관람객이 QR을 스캔해서 자기 폰으로 페이지를 여는 그 순간에는, 관람객 본인 폰 쪽에 네트워크가 필요합니다 — 태블릿 자체는 계속 오프라인이어도 괜찮아요.)

**꼭 지켜야 하는 것: 배포/수정 후 태블릿에서 와이파이가 켜진 상태로 한 번은 접속(또는 새로고침)해야 합니다.** 이때 최신 파일이 태블릿에 저장되고, 그 다음부터는 오프라인으로 계속 켜도 됩니다. 행사 당일 현장에 도착하면:
1. 아직 와이파이가 있을 때(또는 행사 준비 중 미리) 앱을 한 번 열어서 처음부터 끝까지 넘겨봅니다.
2. 그 후에는 태블릿을 비행기 모드로 돌리거나 와이파이를 꺼도 앱이 그대로 동작합니다.
3. 나중에 문항 내용을 수정해서 다시 배포한 경우에는, 와이파이가 있는 상태로 한 번 더 열어줘야 새 버전이 태블릿에 반영됩니다(수정 후 자동으로 반영되지 않고, 캐시된 이전 버전이 계속 보일 수 있어요 — 이때는 앱을 완전히 껐다 켜거나 새로고침을 한 번 해주세요).

## 참고

- 폰트(Jua, Noto Sans KR)는 이 앱에서 실제로 쓰는 글자만 골라 담아 `fonts/` 폴더에 내장했습니다(전체 폰트 대비 용량을 크게 줄였어요). 그래서 인터넷 연결 없이도 글자가 항상 정상적으로 표시됩니다.
- **결과 공유는 "카카오톡 공유"가 아니라 "내 폰으로 결과 받기"(QR코드)로 동작합니다.** 이 앱은 관람객 개인 소유가 아닌 지정된 태블릿에서 체험하는 걸 전제로 만들어서, 결과 화면에서 버튼을 누르면 태블릿 화면에 QR코드가 뜨고, 관람객이 자기 휴대폰 카메라로 그 QR을 스캔하면 관람객 본인 폰 브라우저에서 똑같은 결과 화면이 열립니다. QR에는 이미지 파일이 아니라 응답 데이터만 링크 형태로 담기기 때문에 태블릿이 오프라인이어도 QR 생성 자체는 잘 됩니다.
- **관람객 본인 폰 화면(QR로 접속한 화면)에서는 버튼 구성이 달라집니다.** 태블릿 화면에는 "내 폰으로 결과 받기"와 "테스트 다시 하기"가 있지만, QR로 넘어간 본인 폰 화면에는 대신 "📥 결과 이미지 저장"과 "📤 SNS에 공유하기" 버튼이 나옵니다.
  - **결과 이미지 저장**: 취향 유형·설명·해시태그·취향분포까지 담긴 카드 이미지를 만들어 미리보기로 보여주고, "다운로드 후 닫기" 버튼을 누르면 그 이미지가 폰에 저장되면서 창이 자동으로 닫힙니다.
  - **SNS에 공유하기**: 기기가 지원하면(대부분의 최신 안드로이드/아이폰 브라우저) 운영체제의 공유 시트가 뜨고, 그 안에서 인스타그램을 선택해 바로 공유할 수 있습니다. 공유 시트를 지원하지 않는 구형 브라우저에서는 대신 이미지 저장 창이 뜨니, 저장한 이미지를 인스타그램 앱에서 직접 올리면 됩니다. (인스타그램에 앱 없이 자동으로 올리는 공개 기능은 없어서, 이 방식이 웹에서 가능한 가장 가까운 방법입니다.)
  - 결과 화면에 보이는 유형과 저장/공유되는 이미지 속 유형은 항상 같은 값에서 만들어지기 때문에 서로 다르게 나오는 일이 없습니다.
- 문항 문구, 타임테이블, 결과 유형 등은 모두 `index.html` 안 `<script>` 태그의 `QUESTIONS` / `SCHEDULE` / `RESULT_TYPES` 객체에서 수정할 수 있습니다. 다만 새로운 텍스트에 지금 내장된 폰트에 없는 글자(예: 특수 한자, 드문 기호)가 들어가면 그 글자만 깨져 보일 수 있습니다 — 이런 경우 알려주시면 폰트 파일을 다시 만들어 드릴게요.
- 문항을 수정해서 재배포했다면 `sw.js` 맨 위의 `CACHE_NAME` 값을 `v3` → `v4`처럼 한 단계 올려주세요. 이렇게 해야 태블릿이 "새 버전이 나왔구나"를 인식하고 캐시를 새로 받습니다(안 올리면 옛날 버전이 계속 보일 수 있어요).
- 도메인을 연결하려면 Vercel 프로젝트의 **Settings → Domains**에서 추가하세요.

## 태블릿에서 주소창 없이 "앱처럼" 실행하기

브라우저 주소창은 웹페이지를 "브라우저로" 열어서 보여줍니다. 이걸 없애려면 태블릿 홈 화면에 아이콘으로 추가해서 그 아이콘으로 열어야 하는데, 이번에 넣은 `manifest.json` + `icons`가 그걸 가능하게 해주는 설정입니다. GitHub에 파일을 올리고 Vercel이 재배포를 마친 뒤, 태블릿에서 아래 순서를 따르면 됩니다.

**아이패드(iOS Safari)**
1. Safari로 배포된 주소(`https://프로젝트명.vercel.app`)에 접속
2. 하단 공유 버튼(⬆️) → **홈 화면에 추가** 선택
3. 이름 확인 후 **추가**
4. 홈 화면에 생긴 아이콘으로 실행 → 주소창 없이 전체 화면으로 열립니다

**안드로이드 태블릿(Chrome)**
1. Chrome으로 배포된 주소에 접속
2. 우측 상단 점 3개 메뉴 → **앱 설치** 또는 **홈 화면에 추가**
3. 설치 후 그 아이콘으로 실행 → 주소창 없이 전체 화면으로 열립니다

**설치했는데도 계속 크롬 주소창이 보인다면 (체크리스트)**

이 앱의 설정(manifest.json, 서비스 워커, 아이콘)은 실제 배포 환경에서 정상 동작이 확인된 상태입니다. 그런데도 설치 후 주소창이 보인다면, 아래 순서로 확인해보세요.

1. **홈 화면 아이콘으로 실행했는지 확인** — Chrome 주소창의 "공유" 메뉴로 남에게 링크만 보낸 걸 열었거나, 즐겨찾기/북마크로 저장한 걸 열면 항상 일반 브라우저 탭으로 열립니다. 반드시 태블릿 홈 화면에 새로 생긴 **앱 아이콘**을 탭해서 열어야 주소창이 없는 전체 화면으로 실행됩니다.
2. **재설치해보기** — 예전에 한 번 "홈 화면에 추가"를 했었다면, 그때는 `manifest.json`이 아직 없거나 잘못된 상태였을 수 있습니다. 그 경우 이미 만들어진 아이콘은 일반 바로가기(북마크)로 고정되어, 나중에 파일을 고쳐도 자동으로 "진짜 앱"으로 바뀌지 않습니다. 기존 홈 화면 아이콘을 삭제한 뒤, 와이파이가 켜진 상태에서 Chrome으로 주소를 다시 열고 처음부터 "앱 설치"를 다시 진행해주세요.
3. **GitHub에 업로드된 파일 구조 확인** — `index.html`과 `manifest.json`, `icons/`, `fonts/`, `sw.js`가 저장소의 **같은 위치(루트)**에 있어야 합니다. 만약 실수로 하위 폴더(예: `deploy/index.html`) 안에 들어가 있다면, 사이트 자체는 열리더라도 `manifest.json`을 찾지 못해 브라우저가 "설치 가능한 앱"으로 인식하지 못합니다. 배포된 주소 뒤에 직접 `/manifest.json`을 붙여 접속했을 때 아이콘 정보가 담긴 텍스트가 그대로 보이는지 확인해보세요(에러 페이지가 뜨면 경로 문제입니다).
4. **Chrome 우측 상단 점 3개 메뉴에 "앱 설치"가 보이는지 확인** — 이 메뉴 항목이 아예 안 보이거나 "홈 화면에 추가"만 보인다면, Chrome이 아직 이 사이트를 설치 가능한 앱으로 인식하지 못한 상태입니다(주로 2번·3번 이유 때문입니다).

**행사장에서 완전히 다른 앱으로 못 빠져나가게 고정하고 싶다면(권장)**
현장 무인 체험 부스처럼 관람객이 홈 버튼을 누르거나 다른 앱으로 나가지 못하게 아예 잠그고 싶다면, 위 방법으로 앱을 설치한 뒤 OS의 "키오스크 잠금" 기능을 추가로 켜주세요.
- 아이패드: **설정 → 손쉬운 사용 → 안내 접근 모드(Guided Access)** 켜기 → 홈 화면에 추가한 아이콘 실행 → 전원 버튼 3번 클릭으로 잠금 시작
- 안드로이드: **설정 → 보안 → 앱 고정(Screen Pinning)** 켜기 → 최근 앱 목록에서 해당 앱 고정 (또는 무료 앱 **Fully Kiosk Browser**를 사용하면 자동 재시작, 화면 꺼짐 방지 등 부스 운영에 더 편한 기능을 쓸 수 있습니다)
